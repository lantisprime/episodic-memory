## §3 Objective

`em-consolidate`'s two digest-apply paths currently archive episodes with no playbook
protection at all (legacy apply) or with playbook protection structurally disabled by a
hardcoded empty id list (clerk apply), and both swallow protection failures silently. After
this slice, every mutating path in `em-consolidate.mjs` resolves protection through one
shared fail-closed resolver, digests inherit the `playbook` marker at all four write sites,
and each apply reports which declarations its writes affected. Provable by
`node tests/test-rfc-015-p1-s2-consolidation.mjs` going from red to green on 24 legs,
including both polarities of every abort.

## §8 Design

### 8.1 Key types

```js
/**
 * @typedef {Object} ProtectionAbort
 * @property {'playbooks'|'protection'} kind — which fail-closed class fired
 * @property {string} reason — human-readable cause, no trailing punctuation
 * @property {string} file — absolute path of the file that caused it
 */

/**
 * @typedef {Object} ProtectionResolution
 * @property {ProtectionAbort|null} abort — non-null means the caller MUST exit 1
 * @property {Map<string,{reason:string,via:string|null}>} [protectedIds] — present iff abort === null
 * @property {string[]} [playbookIds] — declared ids, present iff abort === null
 */

/**
 * @typedef {Object} ConsolidationAdvisory
 * @property {string} project_store — absolute path of the cwd-local store (B-3)
 * @property {Array<{declaration_id:string|null, members:string[], reason:string}>} [protected_declarations]
 * @property {Array<{resolves_to:string, kind:'digest'|'canonical', members:string[]}>} [marker_inheritance]
 * @property {string} note — always present
 */
```

### 8.2 Key invariants

- **One resolver, four callers.** `resolveProtectionOrAbort` is the only place any mutating
  path in `em-consolidate.mjs` derives `protectedIds`. No call site re-derives
  `willArchiveLocal` or re-reads the registry.
- **Two abort classes, two messages.** `kind: 'playbooks'` names a `playbooks.json`;
  `kind: 'protection'` names an `index.jsonl`. A caller never collapses them.
- **Abort precedes advisory, always.** Advisory construction is unreachable on an abort path.
- **Skip is not block.** A protected member removes its cluster from the apply set and is
  reported; the command exits 0.
- **No existing episode is mutated for marker purposes** (B-4). The marker is written only
  onto newly created digest episodes.
- **`protection.mjs` is read-only in this slice**, preserving RFC:141's "INTERACTS,
  UNCHANGED" disposition. All four call sites live in one file, so the helper belongs there.
- **Cross-platform:** `os.tmpdir()` + `path.join` in every fixture; no `sed -i`, no
  `readlink -f`, no GNU-only flags. Negative controls reach the code by argv flag, not by an
  env prefix, so they run under Windows `cmd`.
- **Atomicity:** unchanged. Every write already routes through `atomicReplaceFileSync` or the
  clerk `tmp`+`rename` pair; this slice adds no new write primitive.

### 8.3 Resolution / flow

```text
argv → mode select
  ├─ fold (single | all-projects)
  │     acquire nothing → resolveProtectionOrAbort(scope) → abort? exit 1 : foldStore(protectedIds)
  ├─ legacy cluster
  │     dry-run?  → resolveProtectionOrAbort(scope) → abort? exit 1 : print report + advisory, exit 0
  │     zero-clusters → resolveProtectionOrAbort(scope) → abort? exit 1 : print empty envelope, exit 0
  │     apply → acquire store lock
  │             → resolveProtectionOrAbort(scope)   [INSIDE lock]
  │             → abort? release lock, exit 1
  │             → filter clusters by protectedIds  → protection_skips
  │             → for each surviving cluster: write digest (marker if any member marked)
  │             → build advisory once → envelope → release lock → print
  └─ clerk apply
        acquire clerk lock
          → resolveProtectionOrAbort(scope)          [INSIDE lock]
          → abort? release lock, exit 1
          → per proposal: protected member → skippedGuard
          → merge → digest (marker if any member marked) | dedupe → no digest, no mutation
          → build advisory once → envelope → release lock → print
```

## §12 Contracts

### `resolveProtectionOrAbort(scopeArg) → ProtectionResolution`

**Input contract:** `scopeArg` is exactly `'local'` or `'global'`. Any other value is a
programming error; the function does not validate it because argv parsing already rejected it
at `em-consolidate.mjs:129-132`.
**Output contract:** a discriminated union on `abort`. When `abort !== null`, `protectedIds`
and `playbookIds` are absent and the caller MUST exit 1. When `abort === null`, both are
present and `protectedIds` is a `Map` (possibly empty). The function NEVER throws and NEVER
returns a partially-populated result.

**State table (exhaustive):**

| State | Condition | Output | Side effects |
|---|---|---|---|
| A. clean local | `scope==='local'`, local `playbooks.json` absent or valid, both `index.jsonl` readable | `{abort:null, protectedIds, playbookIds}` | reads 1-2 index files, 1 playbooks file |
| B. clean global | `scope==='global'`, registry healthy, every registered `playbooks.json` absent or valid | `{abort:null, protectedIds, playbookIds}` | additionally reads the registry + each registered `playbooks.json` |
| C. local corrupt, local scope | `scope==='local'`, local `playbooks.json` present-but-unparseable | `{abort:{kind:'playbooks', reason:'local playbooks.json present but unparseable (…)', file:'<local>/playbooks.json'}}` | none |
| D. local corrupt, global scope | `scope==='global'`, local `playbooks.json` unparseable, caller passed `abortOnLocalPlaybooks: true` | `{abort:{kind:'playbooks',…}}` | none |
| D2. local corrupt, all-projects fold | `abortOnLocalPlaybooks: false`, cwd project **registered** | `{abort:{kind:'playbooks', file:'<local>/playbooks.json'}}` via the registry loop (`protection.mjs:150-161`) | reads registry |
| D3. local corrupt, all-projects fold, cwd **unregistered** | `abortOnLocalPlaybooks: false`, cwd not in the registry | `{abort:null,…}` — that store is never archived by this fold, so its config cannot make protection unknowable | reads registry |

### `buildConsolidationAdvisory({localDataDir, playbookIds, protectedClusters, markedConsolidations}) → ConsolidationAdvisory|null`

**Input contract:** `localDataDir` is an absolute path. `playbookIds` is the resolver's declared-id
array — the builder **does no file I/O of its own**, which is what keeps its view of the
declaration set identical to the resolver's (review r1 F3: an independent re-read would fail open
on the very file R4d fails closed on). `protectedClusters` is an array of
`{members: string[], reason: string, via: string|null}` and callers pass only playbook-caused
skips; the builder re-filters to `reason === 'protected:playbook-referenced'` as defence in depth.
`markedConsolidations` is an array of `{resolves_to: string, kind: 'digest'|'canonical',
members: string[]}`. Both arrays may be empty.
**Output contract:** returns `null` when both **post-filter** arrays are empty, so the caller omits
the key entirely and output stays byte-identical for non-playbook stores. Otherwise returns a
`ConsolidationAdvisory` with `note` always present. NEVER throws: all computation is wrapped,
degrading to a `note`-only object. Performs zero reads.

**State table (exhaustive):**

| State | Condition | Output | Side effects |
|---|---|---|---|
| A. nothing relevant | both arrays empty | `null` | none |
| B. non-playbook protection only | `protectedClusters` non-empty but every entry filters out (pinned, trigger-bearing-lesson, evidence-linked-violation, consolidates-member, latest-run-record, store-identity-chain, chain-member), `markedConsolidations` empty | `null` — the skip is reported in `protection_skips`, but no declaration may be claimed | none |
| C. playbook protection only | ≥1 entry survives the class-e filter, `markedConsolidations` empty | `{project_store, protected_declarations:[…], note}` where `note` names the recovery path | none |
| D. marker inheritance only | `protectedClusters` empty or fully filtered, `markedConsolidations` non-empty | `{project_store, marker_inheritance:[…], note}` | none |
| E. both | C and D conditions both hold | both arrays present, `note` joins both sentences | none |
| F. `via` not in `playbookIds` | a surviving entry's `via` is absent from the declared set | that entry's `declaration_id` is `null` rather than a fabricated id | none |
| G. declarations unreadable | either array non-empty, `playbooks.json` unparseable | unreachable — REQ-10 guarantees the resolver aborted first, and the builder reads nothing | n/a |
| H. internal throw | any unexpected error | `{project_store, note:'advisory computation failed: <message>'}` | none |

### Decision taken, not deferred — R4c's live trigger

R4b and R4c overlap in a way the RFC text does not anticipate. Once R4b fires, a member of a
**declared** chain is protected, so its cluster is skipped and the substitution R4c describes
can no longer occur for declared chains. R4c's remaining live triggers are (i) a cluster
skipped by playbook protection, and (ii) a **marker-bearing but undeclared** member being
consolidated (the marker alone protects nothing, RFC:148). This plan implements the coherent
superset covering both, rather than a clause with an empty trigger set. Raised once here and
built within the accepted spec; REQ-15 records it in the RFC.

## A.6 Anchor format

- **EDIT** — anchored `ANCHOR → REPLACE` on existing content; change only that span. Never
  rewrite a whole function, never reflow untouched lines, never `Write`-overwrite an existing file.

```js
// realpath-keyed union across cwd-local + global + EVERY registered store
// (em-consolidate.mjs:317-325). Hardcoding [[LOCAL_DIR,'local'],[GLOBAL_DIR,'global']]
// here would (i) drop third-store referencers — a lesson in projC whose evidence
// names a projB chain member would stop protecting it — and (ii) collapse class-d's
// per-store latestByStore buckets, because realpath labels are what keep registered
// stores distinct. Review r1 F1 reproduced both: folded_total 0 -> 11, 11 episode
// files archived, latest-run-record protected true -> false.
// abortOnLocalPlaybooks is likewise a parameter, not `scopeArg === 'local'`.
// The --all-projects fold passes FALSE and keeps its current semantics: the
// registry names the stores it archives, and protection.mjs's registry loop
// (:150-161) already aborts on any REGISTERED project's corrupt config, so an
// unregistered cwd's corrupt file must not abort a fold that never touches it.
// Every other caller passes TRUE — see the willArchiveLocal note below.
function resolveProtectionOrAbort({ scopeArg, storeList, abortOnLocalPlaybooks = true }) {
  const todayStr = new Date().toISOString().slice(0, 10)
  // storeList is REQUIRED and has no default (review r2 F1). The obvious default
  // — [[LOCAL_DIR,'local'],[GLOBAL_DIR,'global']] — is bit-for-bit the r1 F1
  // data-loss defect, so its only reachable effect would be to reintroduce that
  // bug silently in a future call site. Missing input is a fail-closed abort, not
  // a throw, because this function's contract is "never throws".
  if (!Array.isArray(storeList) || storeList.length === 0) {
    return {
      abort: { kind: PROTECTION_ABORT_PROTECTION, reason: 'internal: storeList not supplied', file: null },
      protectedIds: new Map(),
      playbookIds: [],
    }
  }
  const stores = storeList
  const willArchiveGlobal = scopeArg === 'global'
  let registryStores = [], registryRebuilt = false, registryPath = null
  if (willArchiveGlobal) {
    const reg = resolveRegisteredStoresWithStatus()
    registryStores = reg.stores
    registryRebuilt = reg.registryRebuilt
    registryPath = reg.registryPath
  }
  // willArchiveLocal comes from the caller, and is NOT `scopeArg === 'local'`.
  // resolvePlaybookProtection parses the local config regardless of scope
  // (protection.mjs:129-134) but gates the ABORT on this flag (:137). Declarations
  // are local-only (B-3) while playbook episodes live in the global store
  // (RFC-015 Problem 4), so for every path that supersedes or archives, the local
  // file is the ONLY declaration source: an unreadable one makes protection
  // unknowable no matter which store is written. Review r1 F2: with
  // `scopeArg === 'local'` here, a corrupt local playbooks.json under
  // --scope global from an unregistered cwd returned {abort:null, playbookIds:[]}
  // — the R4d fail-open surviving inside the slice that exists to close it.
  const { abort: pbAbort, playbookIds } = resolvePlaybookProtection({
    localStoreDir: LOCAL_DIR,
    willArchiveLocal: abortOnLocalPlaybooks,
    registryStores,
    registryRebuilt,
    registryPath,
  })
  if (pbAbort) {
    return { abort: { kind: PROTECTION_ABORT_PLAYBOOKS, reason: pbAbort.reason, file: pbAbort.file } }
  }
  const protectionRows = []
  for (const [dir, label] of stores) {
    try {
      protectionRows.push(...loadProtectionRows(fs, path, dir, label))
    } catch (e) {
      return {
        abort: {
          kind: PROTECTION_ABORT_PROTECTION,
          reason: `protection index unreadable (${e && e.code ? e.code : (e && e.message) || 'unknown'})`,
          file: path.join(dir, 'index.jsonl'),
        },
      }
    }
  }
  let protectedIds
  try {
    protectedIds = computeProtectedIds(protectionRows, todayStr, playbookIds)
  } catch (e) {
    return {
      abort: {
        kind: PROTECTION_ABORT_PROTECTION,
        reason: `protection computation failed (${(e && e.message) || 'unknown'})`,
        file: path.join(LOCAL_DIR, 'index.jsonl'),
      },
    }
  }
  return { abort: null, protectedIds, playbookIds }
}

// Single emitter so every path prints the identical error shape. Callers that
// hold a lock MUST release it before calling this (process.exit skips finally).
function emitProtectionAbort(abort, mode) {

    mode,
    code: `protection-abort:${abort.kind}`,
    message: `em-consolidate: aborting ${mode} — ${abort.reason} (${abort.file})`,
  }))
  process.exit(1)
}
```

```js
// Splits protected clusters into playbook-caused and other. `allSkips` is what the
// envelope reports; `playbookSkips` is the ONLY input the advisory may speak about.
// Class-e is the sole playbook class (protection.mjs:245-267) and its `via` is the
// CONFIGURED declaration id, which is exactly what the advisory must name.
function partitionProtectionSkips(clusterMemberIdLists, protectedIds) {
  const allSkips = [], playbookSkips = []
  for (const memberIds of clusterMemberIdLists) {
    const hitId = memberIds.find(id => protectedIds.has(id))
    if (!hitId) continue
    const hit = protectedIds.get(hitId)
    const rec = { members: memberIds, reason: `protected:${hit.reason}`, via: hit.via }
    allSkips.push(rec)
    if (hit.reason === PLAYBOOK_PROTECTION_CLASS) playbookSkips.push(rec)
  }
  return { allSkips, playbookSkips }
}
```

### Listing L10 — `buildConsolidationAdvisory` (step 1.14, APPEND to `scripts/lib/playbook-registration.mjs`)

```js
/**
 * buildConsolidationAdvisory({ localDataDir, protectedClusters, substitutedClusters })
 *   → ConsolidationAdvisory | null
 *
 * RFC-015 R4c. Two live triggers:
 *   (i)  a cluster skipped because a member belongs to a DECLARED chain — the
 *        operator needs to know why curation did not happen, and how to allow it;
 *   (ii) a marker-bearing but UNDECLARED member consolidated into a digest — the
 *        marker alone protects nothing (RFC-015:148), so this one really is the
 *        content substitution Problem 2a describes.
 *
 * Returns null when neither fired, so a non-playbook store's stdout stays
 * byte-identical to the pre-RFC-015 shape (Principle 6, zero cost when unused).
 * Advisory only — nothing here blocks (B-1). Never throws.
 *
 * @param {{
 *   localDataDir: string,
 *   protectedClusters?: Array<{members: string[], reason: string, via: string|null}>,
 *   substitutedClusters?: Array<{resolves_to: string, kind: 'digest'|'canonical', members: string[]}>,
 * }} args
 */
// Review r2 F3: ONE constant, shared by partitionProtectionSkips (which matches by
// prefix) and by the advisory (which matched the literal exactly). Two duplicated
// literals would drift the moment a second playbook protection class is added:
// the partition would classify it as protection while the advisory silently dropped
// it, yielding a skip with no advisory and no error. Defined here rather than
// exported from protection.mjs so that file stays byte-identical (RFC:141).
export const PLAYBOOK_PROTECTION_CLASS = 'playbook-referenced'
export const PLAYBOOK_PROTECTION_REASON = `protected:${PLAYBOOK_PROTECTION_CLASS}`

export function buildConsolidationAdvisory({ localDataDir, playbookIds, protectedClusters, markedConsolidations }) {
  const declared = new Set(Array.isArray(playbookIds) ? playbookIds : [])
  // Callers MUST pass only playbook-caused skips (partitionProtectionSkips's
  // playbookSkips). This filter is defence in depth: an advisory that calls a
  // `pinned` or `trigger-bearing-lesson` skip a declared playbook chain, and tells
  // the operator to edit a playbooks.json that may not exist, is a false statement
  // (review r1 F3). Belt and braces, because both apply paths feed this and the
  // clerk's skippedGuard also carries non-protection entries like
  // `canonical-superseded` (em-consolidate.mjs:1935).
  const prot = (Array.isArray(protectedClusters) ? protectedClusters : [])
    .filter(p => p && p.reason === PLAYBOOK_PROTECTION_REASON)
  const marked = Array.isArray(markedConsolidations) ? markedConsolidations : []
  if (prot.length === 0 && marked.length === 0) return null
  const base = { project_store: localDataDir }
  try {
    const notes = []
    const out = { ...base }
    if (prot.length) {
      out.protected_declarations = prot.map(p => ({
        declaration_id: declared.has(p.via) ? p.via : null,
        members: p.members,
        reason: p.reason,
      }))
      notes.push(
        `${prot.length} cluster(s) were not consolidated because a member belongs to a declared playbook chain; ` +
        'to allow consolidation, remove the declaration from this project\'s playbooks.json first'
      )
    }
    if (marked.length) {
      // NOT called a "substitution": these members carry the marker but are NOT
      // declared, so nothing renders them and nothing is being substituted
      // (review r1 F3). The marker is inherited so the digest stays discoverable
      // by the R1 detection predicate and by em-doctor's playbook-unregistered check.
      out.marker_inheritance = marked.map(s => ({
        resolves_to: s.resolves_to,
        kind: s.kind,
        members: s.members,
      }))
      notes.push(
        `${marked.length} consolidation(s) folded a playbook-marked but UNDECLARED episode; the marker was ` +
        'inherited by the result, whose body is now the auto-generated digest — re-curate it before declaring it'
      )
    }
    out.note = notes.join('; ')
    return out
  } catch (e) {
    return { ...base, note: `advisory computation failed: ${e && e.message ? e.message : String(e)}` }
  }
}
```

### Listing L12 — RFC edits (step 1.17)

(a) Appended to R4(a):

> On the clerk `dedupe` action no digest is written — members are superseded onto an existing
> canonical episode — so there is no new episode to mark and no existing episode is mutated
> (B-4). The advisory names the canonical id as the resolution target instead. Because canonical
> selection would otherwise be cluster-build order, a marker-bearing member is preferred as
> canonical when the cluster contains one: otherwise a marked member is superseded onto an
> unmarked canonical and the R1 detection predicate silently desyncs, since the chain terminal
> would no longer carry `playbook: true`.

(b) Appended to R4(b):

> This **extends** RFC-011 R5(b)'s binding rather than mirroring it, and the extension is wider than
> a call-site count: R5(b) bound **archival** consumers (`em-prune`, `em-consolidate
> --fold-superseded`), and the two apply paths do not archive at all — they supersede in place
> (`em-consolidate.mjs:1105-1112`, `:1253-1280`), while only `foldStore` (`:254-300`) moves files
> into `archived/`. R4b therefore extends R5(b) from archival consumers to **supersession**
> consumers, and adds a consumer-registry read on `--scope global` applies that those paths did not
> previously perform. It also widens the
> accepted denial-of-curation residual: once protection fires on the apply paths, a declared chain's
> own digest is re-anchored by class-e and its members by class-c, so the chain cannot be
> re-consolidated until the operator removes the declaration from `playbooks.json`. There is no
> override flag; `--include-pinned` gates only the pinned-row filter.

(c) Appended to the Non-goals sentence:

> `em-consolidate --clerk --enrich --apply` is out of scope for R4: it revises through `em-revise`
> and archives nothing, and RFC-011 R5(b) binds archival consumers.

(d) Ledger row, replacing `| P1-S2 | pending | — | — | |`:

```js
  const r = spawnSync(process.execPath, [CONSOLIDATE, ...args, ...(BREAK ? ['--break-protection-throw'] : [])],

  let json = null
  try { json = JSON.parse(r.stdout.trim().split('\n').filter(Boolean).pop()) } catch {}
  return { code: r.status, stdout: r.stdout, stderr: r.stderr, json }
}
```
