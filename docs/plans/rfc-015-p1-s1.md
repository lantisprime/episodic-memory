## §7 Safety / Security

Trust boundary: a consent file (`playbooks.json`) gains its first programmatic writer.
`negative-scenario-planner` dispatched on this design (Sonnet seat, this session): verdict
HOLD-1-blocker + 3 minors, all folded below — (G1 BLOCKER) unserialized read-modify-write
proven by live probe → registration now runs INSIDE the already-held store-write lock, new
T17 fixture; (G2) refusal timing already pre-lock in §12 — kept explicit; (G3) 64 KiB
byte-bound re-checked by the writer (schema cannot express it, `playbooks.schema.json:6`);
(G4) symlink disposition pinned to accept-and-convert (repo-wide `atomicReplaceFileSync`
semantics). Fail direction for every write-path validation:
**closed** (refuse, never repair/clamp). Advisory legs are fail-open BY SPEC (B-1:
detection failure degrades to a note; never a non-zero exit on the advisory path).

## §8 Design

### 8.1 New shared module: `scripts/lib/playbook-registration.mjs`

Zero-dep ESM. Owns everything both CLI surfaces share, so `em-store`/`em-revise` get
identical behavior from one implementation (precedent: `scripts/lib/store-identity.mjs`,
RFC-012 P2):

```js
/**
 * @typedef {Object} PlaybookAdvisory
 * @property {boolean} registered
 * @property {string} project_store   // "<abs local project store dir>" e.g. <cwd>/.episodic-memory
 * @property {{id: string, mode: string}} [suggested_entry]  // absent when registered: true
 * @property {string} note
 */
export function buildPlaybookAdvisory({ episodeId, localDataDir, indexRows })
export function registerPlaybook({ episodeId, mode, localDataDir })
export function playbooksPath(localDataDir)  // path.join(localDataDir, 'playbooks.json')
```

- `buildPlaybookAdvisory` — reads via `parsePlaybooksConfig(localStoreDir)` (import from
  `em-trigger-index.mjs`); resolves each declared id with `terminalOf`/`buildChainMaps`
  over the local index rows; returns the RFC:64-71 object. Parse states: absent file →
  `registered: false` + suggested_entry; valid + declared chain (declared id's terminal ===
  episode's chain terminal) → `registered: true`, NO `suggested_entry`, note "declared in
  this project's playbooks.json"; malformed → `registered: false`, note carries the parse
  reason, NEVER writes.
- `registerPlaybook` — the ONLY writer. Flow: read existing file raw → absent: start from
  `{ schema_version: 1, playbooks: [] }` → present: JSON.parse; parse failure → return
  `{ok:false, code:'playbooks-parse', message:'playbooks.json: <parse error message>'}` →
  validate EXISTING doc against schema (validateInstance from
  `scripts/lib/json-instance-validate.mjs` + parser-enforced unique-by-id); invalid →
  `{ok:false, code:'playbooks-invalid', message:<first validation error>}` → upsert
  `{id, mode}` by id (existing id: replace entry, idempotent; new id at maxItems 32:
  `{ok:false, code:'playbooks-full', message:'playbooks.json: playbooks has 32 entries (maxItems); remove one before registering a new id'}`)
  → validate RESULTING doc via the exported `validatePlaybooksShape` (parser's own
  function — unique-by-id included; NOT a reimplementation) → refuse when
  `Buffer.byteLength(serialized, 'utf8') > 64 * 1024`:
  `{ok:false, code:'playbooks-oversize', message:'playbooks.json: resulting document exceeds the 64 KiB bound'}`
  → write atomic temp+rename →
  `{ok:true, entry, created: <bool file was absent>, buildCapped: <bool count(mode==='session_start') > max_playbooks-effective>}`.

CONCURRENCY CONTRACT (NSP G1): `registerPlaybook` performs no locking itself; its CALLERS
(`em-store`/`em-revise`) invoke it inside the store-write-lock try-block they already hold
for the episode write (same `dataDir` = the local store that contains `playbooks.json`).
This serializes registrations exactly like every sibling store write.

### 8.2 Key invariants

- Marker end-to-end path mirrors `pinned` exactly (store flag → fmLine → index field →
  revise inheritance → rebuild whitelist).
- ONE parser (`parsePlaybooksConfig`), ONE chain-walker (`terminalOf`) — exported, not
  reimplemented (R2/F7).
- `registerPlaybook` is the single `playbooks.json` write site in the repo (T8 grep target:
  `grep -rn "playbooks.json" scripts/ | grep -i writ` style sweep + runtime).
- Advisory computation must never throw the store/revise flow: wrap in try/catch; failure
  degrades to `{registered:false, note:'<reason>'}`.
- **Cross-platform:** `path.join` only; temp file in the same dir as target (rename
  atomicity across devices); no shell, no GNU flags.
- **Atomicity:** temp + rename via the same helper family as `atomicReplaceFileSync`.

### 8.3 Flow (em-store; em-revise identical after inheritance resolution)

```text
parse flags → (contradiction? refuse exit 1) → normal store path writes episode+index
  → marker? append playbook:true to fm + index entry
  → --register-playbook? registerPlaybook() → ok? advisory registered:true (+build-cap note)
                                            → refuse? print error JSON, exit 1 (file untouched, episode ALREADY stored)
  → marker && !--register-playbook? buildPlaybookAdvisory() → append to successPayload
```

Ordering decision (T15-driven): the episode store itself SUCCEEDS even when registration is
refused — the refusal names the parse error and exits 1 AFTER printing a payload carrying
`status: 'error'`, `code`, `stored_id` (the episode that DID land). Rationale: B-4
(episode write is unconditional data), T15 asserts refusal + file byte-identical; a
stored-but-unregistered episode is recoverable via re-run with the flag; an aborted store
after a half-flow is not. The seat implements exactly this contract.

| Input | Behavior |
|---|---|
